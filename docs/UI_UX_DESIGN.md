# UI/UXデザイン

## 設計原則

- 利用者本人が自分の情報を入力する。
- コントロールは大きく、シンプルで、予測可能にする。
- 現在のMVPでは通常入力ワークフローのみを使用する。
- テキスト揃え設定は、デフォルトのフォーム画面を圧迫しない形で提供する。
- 状態の表示を色だけに頼らない。
- アクセシビリティのためにネイティブフォームコントロールを優先する。

## 主要画面

- 基本情報
- 写真
- 学歴・職歴
- 免許・資格
- 志望動機、自己PR、本人希望
- 配慮事項シート
- 保存とファイル出力
- 仕上がり見本（フィット表示/拡大表示モード）

## アクセシビリティ

- すべての入力項目にラベルを付与する。
- ネイティブのボタンと入力コントロールを使用する。
- フォーカス状態を視覚的に表示する。
- ステータスメッセージとエラーメッセージに `role=status` と `role=alert` を使用する。
- 書き出し操作では、保存形式と内容をラベル付きのラジオボタンで選び、保存ボタンに選択結果を示す。PDFの制限理由を操作ボタンに関連付ける。
- 通常フォームではEnterキーと上下矢印でDOM順に入力欄を移動できる。
- 学歴・職歴および免許・資格の表では、上下矢印で同じ列、左右矢印で同じ行の入力欄へ移動できる。
- textarea、修飾キー付き操作、radio、checkbox、file、readonlyではブラウザ標準のキー操作を維持する。
- IME変換中およびMac Safariの変換確定イベントでは、Enter・矢印キーによる項目移動を行わない。
- テキスト入力の左右矢印は、カーソルが先頭または末尾にある場合だけ隣の入力欄へ移動する。
